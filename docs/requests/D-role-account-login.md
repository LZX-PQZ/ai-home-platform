# 三端密码登录及本机路演账号

用户明确要求移除跨端业主登录栏，为服务方与运营端提供登录及预置账号。本次同步最新 main e3d5774（含 #176 视觉调整）后修改共享认证、布局、契约、Prisma、冒烟和账号准备脚本；不改 B 的报价内核或扩大 C 的运营数据权限。

## 实现与来源

- 保留 #176 顶栏账号浮层与共享视觉 token，RoleLogin 按当前路径只渲染业主、服务方或平台运营中的一个登录栏，公共首页不显示无关登录栏；未登录的服务方/运营显示各自独立登录页。密码登录完成后重新加载对应工作页，清除旧角色预取缓存；业主列表登录/退出后自动重查，聊天页保留未保存草稿。
- 服务方、运营页面必须通过对应账号会话检查，匿名/错角色/失效凭证由 middleware 跳转各自登录页。公开 API 保持原有公开范围；私有业务 API 继续独立校验。
- 新增 StaffCredential/StaffSession（追加表，不重置旧库）。密码使用原 scrypt 实现，随机盐；cookie 为随机令牌，库内仅保存其 SHA-256。每次读取校验有效期、角色、服务方绑定及当前密码摘要，改密/角色变化使旧会话失效。
- 登录 POST 有同源、安全来源、输入大小、密码格式与每账号限频；在签发事务内重验凭证和绑定。失败不签发 cookie、不泄露密码或存储异常。GET 不续期；DELETE 同源撤销。
- 业主与服务方/运营的密码登录互斥：成功登录清理浏览器的旧密码会话，失败保留原会话。旧版 DEMO_AUTH_ENABLED 模拟接口仅为历史联验兼容，三端密码预览明确关闭该开关。
- 服务方密码会话通过现有兼容读取器接入报价、订单、私有需求详情；显式失效 staff cookie 不回退为旧模拟身份。认证成功是 live，但模拟目录、报价和接单来源不因此升级。
- 运营账号只取得现有页面入口，不自动取得全站私有需求/工单或管理写权限；这些接口尚未定义。

## 准备与交付

先对服务实际使用的数据库执行 `npm run db:setup`，再执行 `npm exec -- tsx scripts/create-roadshow-accounts.ts`。本轮预览库为 `file:./a-preview-20261115.db`，保留原有需求、账号和模型配置。

脚本显式创建 roadshow.owner、roadshow.provider、roadshow.admin；服务方绑定现有 provider-a。每端独立随机密码只写入 `.env.roadshow-accounts.txt`（已被 .gitignore 忽略），不返回到 HTTP、不自动 seed，不覆盖已有账号或交付文件。发生错误事务回滚；账号文件写入失败时不创建账号。
