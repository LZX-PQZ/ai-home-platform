# D：新建需求归属当前登录业主

日期：2026-11-14，基于 main `6b0561b`，处理已登录后新需求仍归 demo-owner 导致无法修改/读取报价的问题。

## 先行协议

- `POST /api/demand` 继续使用公共 DemandInput，成功 `201 envelope(Demand)`、published、live；拒绝客户端指定 ownerId/userId/role/id/status/source，不新增 DTO、依赖或 schema。
- 同源 Origin 校验 → 真实业主会话预检 → 在事务外读取并校验正文 → 写事务内重新读取会话及当前角色 → 创建当前业主的需求 → DTO 验证 → 提交。缺失/跨源 Origin 403；无效/撤销/过期/重复 cookie 401；当前角色非 owner 或预检与写入身份不同 403；非法 JSON/字段 400；存储异常或未知提交结果 503，提示刷新核实。
- 只把最终事务中验证的 userId 写为 ownerId；不 upsert 演示账号，不从客户端身份字段或角色导航推断身份。删除旧的固定 demo-owner 无鉴权创建入口。历史需求归属不自动转移。
- 成功和失败均 private, no-store、Vary: Cookie。输出验证在事务内完成，非法输出/存储失败回滚；不能把 501、mock 或异常当创建成功。
- 使用 main 中现有登录与 B 报价读取接口验收：新账号真实密码登录 → POST 创建 → PUT 修改本人需求 → GET 本人报价列表成功；另一业主对同一需求修改/报价读取均 404。不手工插入需求绕过公开创建接口。
