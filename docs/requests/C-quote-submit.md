## 本次独立交付

提供当前页面内的填写、字段校验、增删项目和本地预览，再由用户明确点击“尝试提交报价”。只通过公共 `apiPost` 发送经 `QuoteSubmissionInput` 校验的字段；不发送预览合计、行金额、身份或状态。预览不发网络请求、不写浏览器存储；刷新页面、刷新详情或离开会丢失填写内容。

金额用人民币分的安全整数，未知单价和行金额为 null。数量大于 0、不超过 1,000,000，最多三位小数；按 D/B 已冻结规则使用整数运算逐行四舍五入到分再求和。字段复用公共输入 Schema；待确认项目仍要求填写原因。接口回执中的金额由服务端决定。

提交期间锁定编辑并防止重复点击；此前没有未知结果的首次请求被 400/401/403/404/普通 409/501/503 拒绝时，显示原因并保留输入，501 不生成成功态。网络中断、500、坏 JSON、错位需求或非 submitted 回执显示结果未知，并锁定表单。结果未知时提供“使用同一标识重试”，仅由用户明确点击后重发同一请求体和同一幂等键。409 `IDEMPOTENCY_CONFLICT` 同样锁定，提示已有报价需核实，不引导换键绕过冲突。仅校验通过且需求匹配、状态 submitted 的回执可展示：mock 说明演示身份报价已保存，不代表真实业务身份或业主已收到；live 标明不等于接受/接单。两者均不确认业主已可查看，并锁定本次表单。

本轮补齐未知结果后的重试规则：重试被拒绝不能证明此前未保存，必须继续保留未知状态和锁定原输入。401 提示保留页面完成身份验证，503 提示服务恢复后手动同键重试；400/403/404/普通 409/501 停止页面重试并提示联系平台核实。尤其 `409 INVALID_STATE` 仅表示当前不能重放历史回执，不得据此解锁编辑、提示刷新或换键重报。重试再次网络异常、500 或坏回执时继续允许同键重试；幂等冲突停止重试。只有取得可验证的成功回执才进入已接收状态。

### 回执明细核对

成功后使用公共 `QuoteDTO` 的服务端回执逐项显示项目编号、名称、单位、数量、单价、行金额及备注，同时显示报价/需求/服务方编号、预计工期和服务端已知小计。不复用本地预览覆盖回执，不在展示层重算金额。同名项目按编号区分，0 分显示为 0.00 元，null 显示待确认；即使 `pendingItems` 为空，只要行金额或单价未知，仍提醒完整总价未确定。接口未返回明细时明确无法逐项核对，不补造项目。

回执来源与 `Quote.source` 分别展示；逐条字段缺省保留未知，不从整份响应推导为 live。演示身份写入虽实际落库，仍显示 mock。成功后的表单继续锁定，401/501/坏回执不会展示成功明细。页面说明已更新为演示报价可提交，真实接单与业主报价页面接线仍待完成。

## 幂等请求头接入

- 复用公共 `IDEMPOTENCY_KEY_HEADER` 与 `IdempotencyKey`，通过 `apiPost` 的 `headers` 发送；不往 `QuoteSubmissionInput` 加字段，不引入客户端身份或服务端摘要实现。完整协议见 `D-quote-idempotency.md`。
- 每个表单使用独立内存会话。首次点击提交后才用浏览器 `crypto.randomUUID()` 生成键，并按公共 Schema 校验；预览和编辑本身不生成键、不发请求。浏览器不支持安全生成或键不合法时明确提示本次未发送，不使用弱随机数降级。
- 未编辑时重新预览及允许的失败重试沿用原键和规范化输入；任何字段修改、增删明细均使旧键失效，下一次提交生成新键，即使编辑后改回原值。需求 ID、行顺序、null/0 或任一提交字段变化也不能复用旧键。
- 网络异常、坏回执、服务端异常和幂等冲突后保留原键及输入。仅可恢复的未知状态显示“使用同一标识重试”，由用户明确点击后重发同一请求体和同一幂等键；重试不会自动换键。未知后的重试拒绝继续锁定，不能回到可编辑状态并使旧键失效。
- 键和内容仅保存在当前页面，刷新详情、刷新页面、导航离开或关闭页面都会丢失；这不提供跨刷新、跨标签页、跨设备去重。结果未知时先保留页面并联系平台核实，不能刷新后直接重新报价。
- 未新增运行时 mock。C 的重试测试使用隔离合成输入和响应，用于验证前端状态与同键同体行为，不代替真实身份及业主读取闭环验收。

## D 已确认的公共输入

以下交接字段已由 D 的 `QuoteSubmissionInput` 冻结，具体校验以 `src/contracts` 为准，参见 `D-quote-submission-contract.md`：

| 字段 | 类型、必填性与含义 |
|---|---|
| demandId | 必填 Id，必须对应可报价的已发布需求 |
| items | 必填 1–20 行明细数组 |
| items[].code | trim 后必填且本次报价内唯一的行标识，不超过 100 字；同名项目依靠 code 区分 |
| items[].name | 必填非空名称 |
| items[].unit | 必填，复用 QuoteItem 的 m2/piece/job |
| items[].quantity | 必填正数，最多三位小数，上限 1,000,000 |
| items[].unitPriceCents | 必填 Money 或 null；null 表示待确认，0 表示明确零元 |
| items[].note | 必填字符串，可空；待确认项目建议要求说明 |
| estimatedDays | 必填正整数，复用 Quote 的预计工期约束 |

禁止客户端指定 providerId、报价 id、status、amountCents、knownTotalCents、pendingItems。providerId 从服务端已认证的服务方身份取得；各行金额、合计、待确认项和提交状态由 B 的服务端逻辑计算。D 需提供身份/数据访问基础设施和必要数据库适配。角色导航不能当作身份认证。

公共输入示例（编号和数值均为合成输入；实际请求须使用存在且可报价的非演示需求，不能直接提交此示例）：

```json
{
  "demandId": "example-published-demand",
  "items": [
    {"code": "line-1", "name": "防滑施工", "unit": "m2", "quantity": 12.5, "unitPriceCents": 8000, "note": "含人工"},
    {"code": "line-2", "name": "基层修复", "unit": "job", "quantity": 1, "unitPriceCents": null, "note": "现场测量后确认"}
  ],
  "estimatedDays": 10
}
```
