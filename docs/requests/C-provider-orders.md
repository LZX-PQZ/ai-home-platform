- 用户场景：已认证服务方在 `/provider/orders` 只读查看自己已确认承接的需求及履约状态。
- 当前阻塞（2026-11-14，基于 main `d6255e1`，已含 PR #81、#82）：main 没有订单公共契约、接单关系或按已认证服务方过滤的查询接口；`GET /api/quote` 仍为无参数固定 mock。`/provider/orders` 已用该接口展示只读演示报价，并明确未按当前服务方身份过滤，不能据此确认“我的接单”或真实履约。

## 请 D 确认的最小只读协议

建议 `GET /api/provider/orders`，由服务端根据当前已验证服务方身份过滤，不接受客户端指定当前身份的 providerId。以下路径和 OrderSummary 均为待 D 确认的提案，尚未加入公共契约，当前页面不会请求此路径。

若 D 先提供“本人报价”只读查询，请另行明确路径、状态范围和错误规则，复用公共 `Quote[]`；submitted 只能表示已提交报价，不能作为接单记录。C 不自行增加查询参数或在浏览器按 providerId 过滤全量数据。已冻结的 `GET /api/quote?demandId=...` 属于业主比较接口，服务方和管理员应为 403，不能复用为服务方“我的接单”。

## 身份、状态与失败规则

- 身份来自服务端认证，角色导航不是身份来源；未认证、过期或撤销会话为 401，无服务方权限或当前绑定无效为 403。同一事务核验会话、当前账号及服务方绑定，并据此过滤数据，不能只在页面隐藏其他服务方记录。演示模式可使用 D 已提供的固定演示身份，但仍需验证服务端会话并标 mock，不能允许客户端任选 providerId 冒充本人。
- 经授权且没有接单时返回成功空数组；网络失败、权限问题、501/503 不得转换为成功空数组或返回默认演示订单。
- 所有失败复用 ApiFailure；接口尚未实现为 501，存储不可用或读取数据校验失败为 503。个性化查询的成功与失败响应均应使用 `Cache-Control: private, no-store`、`Vary: Cookie`，避免跨身份缓存泄露。分页、排序及总数如需要，由 D 先定义，C 不猜测查询参数。
- 请明确接单关系的生成时机、同一需求多个服务方的归属、报价接受与接单创建的一致性，以及取消/拒绝是否需要新增状态。既有未签约需求和旧 mock 不自动变成接单记录。

## 交接验收

1. 两个服务方分别只能读取自己的接单；伪造参数、请求头或角色导航不能扩大权限。撤销/过期会话、角色或绑定变化均被重新校验，切换账号不能读到前一身份的缓存。
2. submitted 报价、其他服务方报价、未签约需求不会出现在当前服务方列表；每条接单能追溯同一需求及 accepted 报价。
3. 空列表、401/403、501、503 和刷新后的状态变化可区分，错误不会保留旧记录冒充最新结果。
4. 数据来源明确，演示身份和历史 mock 不因落库变为 live；混合、缺失、非法来源与空列表按 D 确认的协议验收。mock 不表示真实履约；状态和金额均按公共契约校验。
