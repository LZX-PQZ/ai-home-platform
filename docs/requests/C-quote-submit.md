# C → D/B：报价提交契约与接口

- 申请角色：C；状态：待 D/B 确认并合入。
- 场景：服务方在 `/provider/demand/[id]` 填写明细和预计工期，提交后业主能在该需求的报价对比中查看。
- 当前阻塞：main 的 `POST /api/quote` 返回 501，公共契约只有 Quote 输出，没有提交输入、服务方身份来源或写入后的查询协议。C 不自行定义替代提交 DTO，不发送试探性写入。

## 本次独立交付

只提供当前页面内的填写、字段校验、增删项目和本地预览；使用现有 Money、QuoteItem、Quote 的字段校验和类型。预览没有报价 ID、服务方 ID、提交状态或成功信封，不写数据库或浏览器存储。页面刷新、刷新详情或离开页面会丢失填写内容；业主不可见。提交按钮禁用并说明接口未开放。

金额用人民币分的安全整数，未知单价和行金额为 null。为支持面积，数量最多三位小数；本地预览以整数运算将每行金额四舍五入到分，再求和，明确不是最终计价规则。项目名称与备注分别限制 100、1000 字，最多 20 行，数量须大于 0，预计工期为正安全整数。这些是 C 本地输入限制，需 D/B 确认正式契约和服务端规则。

## 请 D 定义公共输入，B 实现接口

建议由 D 在 `src/contracts` 增加并导出报价提交 Schema/类型，以下仅为待确认提案：

| 字段 | 类型、必填性与含义 |
|---|---|
| demandId | 必填 Id，必须对应可报价的已发布需求 |
| items | 必填非空明细数组，数量上限待确认 |
| items[].code | 必填且本次报价内唯一的行标识，字符串；同名项目依靠 code 区分，是否服务端重建请明确 |
| items[].name | 必填非空名称 |
| items[].unit | 必填，复用 QuoteItem 的 m2/piece/job |
| items[].quantity | 必填正数，允许的小数位数、上限及舍入规则由 D/B 确认 |
| items[].unitPriceCents | 必填 Money 或 null；null 表示待确认，0 表示明确零元 |
| items[].note | 必填字符串，可空；待确认项目建议要求说明 |
| estimatedDays | 必填正整数，复用 Quote 的预计工期约束 |

禁止客户端指定 providerId、报价 id、status、amountCents、knownTotalCents、pendingItems。providerId 从服务端已认证的服务方身份取得；各行金额、合计、待确认项和提交状态由 B 的服务端逻辑计算。D 需提供身份/数据访问基础设施和必要数据库适配。角色导航不能当作身份认证。

示例提案（不是本次已接通的协议；数值是测试输入，不是服务方真实报价）：

```json
{
  "demandId": "demo-demand",
  "items": [
    {"code": "line-1", "name": "防滑施工", "unit": "m2", "quantity": 12.5, "unitPriceCents": 8000, "note": "含人工"},
    {"code": "line-2", "name": "基层修复", "unit": "job", "quantity": 1, "unitPriceCents": null, "note": "现场测量后确认"}
  ],
  "estimatedDays": 10
}
```

## 响应、查询与交接验收

- `POST /api/quote` 成功返回公共 `envelope(Quote)`，明确 200/201 语义；只有写入成功才能返回 submitted。mock 必须保持 mock，不冒充真实持久化。
- 失败使用 ApiFailure：400 校验错误、401/403 身份或权限问题、404 需求不存在、409 需求不再可报价或冲突、501 尚未实现、503 存储不可用。D 已在 main 提供保留 HTTP 状态和业务错误码的 apiPost / ApiClientError；报价接口就绪后 C 用它展示错误并保留输入，501 不能显示成功。
- 需确认重复提交/重试幂等约定，避免超时后重复生成报价。
- B 明确按 demandId 查询报价的公共协议，并让业主对比页读到刚提交的同一报价。仅有本地预览不能完成“提交结果能被业主查看”的验收。
- D 更新 docs/API.md、契约和基础设施；B 实现 quote 接口、服务端计价及查询；C 等合入 main 后再接提交。
- 使用两个需求验证数据隔离、两个同名项目验证 code 不混淆；含 null 的报价只展示已知金额小计，未知费用不能按零计算或宣称最终总价。
- 确认分数数量的半分舍入、溢出、非法数字、需求状态变化、重复提交、未授权、失败重试和 mock/live 标识后，再完成端到端验收。
