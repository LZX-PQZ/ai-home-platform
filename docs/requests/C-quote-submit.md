# C → D/B：报价提交契约与接口

- 申请角色：C；状态：D 已冻结输入契约与整数计价规则，身份基础设施已提供；C 已接提交调用与结果反馈，B 的写入、查询和幂等仍待接通。
- 场景：服务方在 `/provider/demand/[id]` 填写明细和预计工期，提交后业主能在该需求的报价对比中查看。
- 当前阻塞：`POST /api/quote` 对合法输入仍返回 501；真实会话适配器、报价写入及写入后的查询协议未接通。输入使用 D 已合入的 `QuoteSubmissionInput`，身份只能由服务端验证。前端调用完成不代表端到端提交已完成。

## 本次独立交付

提供当前页面内的填写、字段校验、增删项目和本地预览，再由用户明确点击“尝试提交报价”。只通过公共 `apiPost` 发送经 `QuoteSubmissionInput` 校验的字段；不发送预览合计、行金额、身份或状态。预览不发网络请求、不写浏览器存储；刷新页面、刷新详情或离开会丢失填写内容。

金额用人民币分的安全整数，未知单价和行金额为 null。数量大于 0、不超过 1,000,000，最多三位小数；按 D/B 已冻结规则使用整数运算逐行四舍五入到分再求和。字段复用公共输入 Schema；待确认项目仍要求填写原因。接口回执中的金额由服务端决定。

提交期间锁定编辑并防止重复点击；400/401/403/404/409/501/503 显示失败原因并保留输入，501 不生成成功态。网络中断、500、坏 JSON、错位需求或非 submitted 回执显示结果未知，并锁定表单等待人工核实，不自动重发。仅校验通过且需求匹配、状态 submitted 的回执可展示：mock 明示不代表真实保存，live 标明不等于接受/接单；两者均不确认业主已可查看，并锁定本次表单。

## D 已确认的公共输入

以下交接字段已由 D 的 `QuoteSubmissionInput` 冻结，具体校验以 `src/contracts` 为准，参见 `D-quote-submission-contract.md`：

| 字段 | 类型、必填性与含义 |
|---|---|
| demandId | 必填 Id，必须对应可报价的已发布需求 |
| items | 必填 1–20 行明细数组 |
| items[].code | trim 后必填且本次报价内唯一的行标识，不超过 100 字；同名项目依靠 code 区分 |
| items[].name | 必填非空名称 |
| items[].unit | 必填，复用 QuoteItem 的 m2/piece/job |
| items[].quantity | 必填正数，最多三位小数，上限 1,000,000 |
| items[].unitPriceCents | 必填 Money 或 null；null 表示待确认，0 表示明确零元 |
| items[].note | 必填字符串，可空；待确认项目建议要求说明 |
| estimatedDays | 必填正整数，复用 Quote 的预计工期约束 |

禁止客户端指定 providerId、报价 id、status、amountCents、knownTotalCents、pendingItems。providerId 从服务端已认证的服务方身份取得；各行金额、合计、待确认项和提交状态由 B 的服务端逻辑计算。D 需提供身份/数据访问基础设施和必要数据库适配。角色导航不能当作身份认证。

公共输入示例（数值是测试输入，不是服务方真实报价；实际写入仍未接通）：

```json
{
  "demandId": "demo-demand",
  "items": [
    {"code": "line-1", "name": "防滑施工", "unit": "m2", "quantity": 12.5, "unitPriceCents": 8000, "note": "含人工"},
    {"code": "line-2", "name": "基层修复", "unit": "job", "quantity": 1, "unitPriceCents": null, "note": "现场测量后确认"}
  ],
  "estimatedDays": 10
}
```

## 响应、查询与交接验收

- `POST /api/quote` 成功返回公共 `envelope(Quote)`，明确 200/201 语义；只有写入成功才能返回 submitted。mock 必须保持 mock，不冒充真实持久化。
- 失败使用 ApiFailure：400 校验错误、401/403 身份或权限问题、404 需求不存在、409 需求不再可报价或冲突、501 尚未实现、503 存储不可用。C 已使用公共 apiPost / ApiClientError 展示错误并保留输入，501 不能显示成功。
- 需确认重复提交/重试幂等约定，避免超时后重复生成报价。
- B 明确按 demandId 查询报价的公共协议，并让业主对比页读到刚提交的同一报价。仅有本地预览不能完成“提交结果能被业主查看”的验收。
- D 继续完成真实会话与必要共享协议；B 实现 quote 写入、权限/状态检查、幂等及查询；合入 main 后 C 再完成真实身份与业主可见的端到端验收。
- 使用两个需求验证数据隔离、两个同名项目验证 code 不混淆；含 null 的报价只展示已知金额小计，未知费用不能按零计算或宣称最终总价。
- 确认分数数量的半分舍入、溢出、非法数字、需求状态变化、重复提交、未授权、失败重试和 mock/live 标识后，再完成端到端验收。
